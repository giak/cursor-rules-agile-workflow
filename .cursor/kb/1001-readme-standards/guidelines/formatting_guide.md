# README Formatting Guide

This guide outlines the recommended formatting practices for project README.md files to ensure readability and consistency.

## General Principles

- Use proper Markdown syntax
- Maintain a consistent style throughout the document
- Keep line length under 120 characters
- Use relative links for repository files
- Add alt text to all images

## Headings

- Use `#` for the main title only (project name)
- Use `##` for main sections
- Use `###` for subsections
- Use `####` for additional nested levels
- Use Title Case for section headings (capitalize main words)

## Text Formatting

- Use **bold** (`**text**`) for emphasis and UI elements
- Use _italic_ (`*text*`) for new terms and parameters
- Use `code` (`` `code` ``) for code snippets, commands, and filenames
- Use > blockquotes for important notes or quotes

## Lists

- Use unordered lists (`-` or `*`) for items without specific order
- Use ordered lists (`1.`, `2.`, etc.) for sequential steps
- Maintain consistent indentation for nested lists (2 or 4 spaces)

## Code Blocks

- Use fenced code blocks with language specification
- Include the language name after the opening backticks for syntax highlighting
- Prefer code examples that can be copied and run without modifications

## Links

- Use descriptive link text (avoid "click here")
- Use relative links for repository files
- Use absolute links for external resources
- Use reference-style links for repeated URLs

## Images

- Always include alt text
- Use relative paths for repository images
- Keep image file sizes reasonable (optimize before adding)
- Consider using a thumbnail with link to full-size image for large images

## Tables

- Use tables for structured data
- Include header row and alignment indicators
- Keep tables simple and readable

## Badges

- Place badges at the top of the README after the title
- Keep badges on a single line when possible
- Use only relevant badges (avoid badge overload)

## Special Sections

### Table of Contents

- Consider generating Table of Contents (TOC) for longer READMEs
- Use reference-style links for TOC entries
- Use anchor links to sections

### Admonitions/Notes/Warnings

- Use blockquotes with strong emphasis for warnings and important notes
- Consider using emoji for visual differentiation

## File Organization

- Keep the main README.md concise
- Consider moving very detailed documentation to separate files
- Use links to reference additional documentation files
